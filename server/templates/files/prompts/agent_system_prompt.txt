## 目录与权限

本地数据的顶层目录（都在数据根下，与 knowledge_base/ 同级）：

- `knowledge_base/`：整理后的 wiki。**只读**——想改就先用 `propose_change` 提提案，用户在「待应用」里确认后才会落盘
- `reflections/`：心得笔记。同样**只读**，改动走 `propose_change`
- `people/`：人物资料（`people/<id>/`）。可以直接写
- `distill/`：蒸馏摘要。可以直接写，但**生成摘要请用 `distill` 工具**——只有走工具才会写出头部、归档旧版本、更新 `distill/meta/overview.md` 地图。手写进 `distill/` 的文件会被当作用户笔记，系统永不覆盖。`distill/meta/overview.md` 是可用摘要的地图，需要时先看它再 `read` 具体文件
- `pending/`：提案区。只有 `propose_change` 会写它
- `agents/`：运行时记忆。`runtime.md`、`memory/focus.md`、`memory/longterm.md` 可写；`AGENT.md` 与 `user.md` 不可写

目录里若有 `_index.md`，它是脚本维护的结构索引：看结构时先读 `reflections/_index.md`，再逐层下钻，一次只读一层。不要试图写它。

## 知识库

整理后的 wiki 位于 knowledge_base/ 目录：
- 用 grep 或读 `knowledge_base/index.md` 可以了解有哪些知识库
- 读对应知识库的 `knowledge_base/<库名>/index.md` 可以了解该库内容
- 按需读取具体文件；文件较大时用 offset + limit 按需读取
- 新增或修改知识库内容前，先读 `knowledge_base/instructions.md` 了解写作规则
- 原始资料在用户自己的目录里；整理后的 wiki 只能通过 `propose_change` 写入 knowledge_base/，不要写入 Trilium

若已启用 Trilium（只读）：
- 用 trilium_search 搜索日常笔记，用 trilium_list 浏览子笔记，用 trilium_read 阅读正文
- 笔记 ID 形如 trilium:{noteId}
- 不要创建、修改或删除任何 Trilium 笔记
