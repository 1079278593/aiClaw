# 对话里勾选领域

> 状态：**阶段 1（注入）与阶段 2（勾选）已实现。**
> 写于 2026-11。一次对话可以勾上「情感」「理财」「运动」这类领域。勾上之后，这一轮多带该领域的规则和目录，不带文章正文。
> 不改人物档案、心得笔记、统一记忆图。不在这一版做向量检索。

---

## 0. 使用场景

一次对话里，除了已经固定带上的系统提示、记忆和对话状态，还可以勾上一到两个领域。

勾上「情感」之后，模型按情感这套规矩说话，并且知道该去读哪几篇文章。文章本身仍在磁盘上，模型用现有的 `read` 自己打开。不勾则这一轮与现在完全一样。

已拍板：

| 问题 | 结论 |
|---|---|
| 领域放在哪 | `knowledge_base/<领域名>/`。用子目录做物理隔离，不另开一棵目录树 |
| 勾上之后带什么 | 该领域的 `rules.md` 全文，加上手写的 `index.md`。文章不带 |
| 规则和知识是否分开 | 分开。规则每轮都在，文章按需读 |
| 一次能勾几个 | 最多 2 个。规则加目录合计不超过 2000 token |
| 要不要向量 | 不要。原文是唯一可核对的事实，目录只负责指路 |

---

## 1. 为什么不新开目录

`knowledge_base/<库名>/` 已经按目录隔开。情感、理财、运动各是一个子目录，文件不会混在一起。

再在外面建 `experts/`，同一篇文章会有两个家，以后对不齐。隔离靠的是「只有勾选的领域进入这一次对话」，不是再复制一份。

现在缺的是两件事，这一版只补这两件：

1. 规则是全局的。`knowledge_base/instructions.md` 管所有库怎么写文章，勾上「情感」时不能拿它当情感的立场。
2. 勾选没有接进对话。知识库现在只是模型自己可以去读的文件，不会因为这一轮勾了什么而改变系统提示。

`instructions.md` 保持原样，继续只服务「怎么整理知识库」。每个领域自己的立场写在该目录的 `rules.md`，不写进 `AGENT.md`。写进宪法会让没勾选的对话也带上这套规矩。

## 2. 一个领域目录里有什么

```text
knowledge_base/
  instructions.md          全局写作说明。不因勾选而注入
  情感/
    rules.md               立场。勾选后整篇注入
    index.md               手写目录：文件名加一句话。勾选后整篇注入
    <文章>.md              正文。不注入，模型用 read 打开
  理财/
    rules.md
    index.md
    <文章>.md
```

| 文件 | 谁写 | 勾选后 |
|---|---|---|
| `rules.md` | 新建领域时生成模板，之后只由人改 | 整篇带上 |
| `index.md` | 新建领域时生成空表，之后只由人加行 | 整篇带上 |
| 文章 | 人或现有整理流程 | 不带 |
| `_index.md` | 服务端按目录自动维护 | 不带。它只有文件名，没有一句话说明，不够指路 |

可勾选的领域 = `knowledge_base/` 下存在且非空的 `rules.md` 的子目录。没有 `rules.md` 的目录（含现有的「示例」）不出现在勾选列表里。`index.md` 可以没有：没有时只注入规则，并在块里写明「这个领域没有目录」。

`rules.md` 里必须写清何时去读文件。否则模型会拿目录那一行直接回答。模板首段固定为：

```text
涉及具体数字、原话、步骤或这个领域里已经写过的结论时，先按下面的目录用 read 打开对应文件，再回答。目录里的一句话不是正文。
```

其后才是这个领域自己的立场。例如情感写「先澄清情绪，不急着给建议」；理财写「不报具体买卖，先问期限和能承受的亏损」。

## 2.1 新建领域只做一次

网页上现在不能建知识库目录。心得有「新建文件夹」，知识库的文档浏览器只能打开已经存在的文件。`PUT /api/documents/content` 在父目录不存在时直接失败，不会顺手建目录。

阶段 2 在知识库一侧加一个「新建领域」。输入目录名（如「情感」），服务端一次做完：

- 建立 `knowledge_base/<名>/`
- 写入 `rules.md`：首段用上面的固定模板，后面留空行给人写立场
- 写入 `index.md`：只有表头，没有文章行

目录、`rules.md`、`index.md` 任一已经存在就拒绝，不覆盖。生成之后这两个文件只在文档浏览器里改，不再生成第二次。

新增文章时**不**自动改 `index.md`。自动补行会冲掉人写的那一句话。新文章的一行仍由人自己加。`_index.md` 继续由索引器自动维护，与这次创建无关。

`index.md` 沿用现有知识库的表格：一行一篇，第一列是文件名或链接，第二列是一句话。不在这里贴正文。

## 3. 怎么进这一轮对话

勾选记在**这一条会话**上，不记在全局开关里。换一条对话，勾选不跟着走。

```jsonc
// Session 上新增
{ "experts": ["情感", "理财"] }
```

只存领域目录名，不存文件内容。发送时现读 `rules.md` 和 `index.md`，改文件后下一轮生效，不用重勾。

装配放在 `buildSystemBlocks` 里，单独一块，名字 `experts`，排在记忆之后、对话状态之前。

预算没有「按优先级丢掉某一块」的实现。`assembleContextBudget` 对每个系统块只做一件事：超过**该块自己的** `max` 就整块不带。各块加起来仍放不进窗口时，整轮直接失败（「本轮内容超出上下文」），不会先丢领域再留对话状态。所以领域必须是**一个**块、`max` 为 2000，超限只丢这一块，不能写成「比对话状态先被淘汰」。

一块的形状：

```text
<专家 领域="情感">
文章都在 knowledge_base/情感/ 下。用 read 时路径写成 knowledge_base/情感/<文件名>，不要用目录里的相对链接。

（rules.md 全文）

目录：
（index.md 全文；没有则写「这个领域没有目录」）
</专家>
```

这一行路径由服务端按目录名拼出来，不从 `index.md` 里摘。现有知识库目录用的是 `[文章.md](文章.md)` 这种相对链接，而 `read` 只认数据目录下的完整相对路径，例如 `knowledge_base/情感/文章.md`。不写前缀，模型会按链接去读 `文章.md`，文件不存在，勾选就只剩规则、正文永远打不开。

两个领域写在同一块里，按勾选顺序拼接。token 用 `estimateTokens`。

| 限制 | 值 | 超出时 |
|---|---|---|
| 一次勾选 | 最多 2 个 | 接口拒绝，不静默丢掉其中一个 |
| 单个 `rules.md` | 1200 token | 这个领域整段不注入（没有规则，目录也不带），另一个领域仍注入 |
| 单个 `index.md` | 800 token | 规则照常注入，目录换成一行「目录超限，未注入」 |
| 整块 | 2000 token | 整块不注入，记日志。不截成半段规则 |
| 目录已被删或 `rules.md` 变空 | — | 跳过这一段，另一个领域仍注入 |

规则和目录分开封顶。若只设整块 2000，一篇写长了的 `index.md` 会把同块里的规则一起挤掉，勾选等于没勾。半段规则比不注入更糟，所以超限不截断。

这一块要出现在上下文来源里（`collectContextSources`），标上实际 token 和 2000 的上限。不可在该页编辑：内容以领域目录里的文件为准，手改注入结果会和文件分叉。

人物会话、心得会话、普通聊天都能勾。勾选不改变折叠、人物整理、档案注入。

两套资料同时在场时的分工：领域规则管语气和禁区，人物的档案与当前判断管「这个人现在怎样」。事实以人物资料为准，不从领域文章里推断这个人。

手动「整理」和自动整理**不带**领域块。这两条路径走同一个 `chatStream`，只靠 `omitTools` 区分。若不显式跳过，整理模型会按「不给建议」之类的领域规矩去写简报。折叠（`foldDialogueState`）不用系统块，不受影响。模型 `read` 到的文章正文仍按现有规则缩短，不为领域开例外。

## 4. 接口与界面

- `POST /api/experts`：body `{ id }`。按 §2.1 一次建出目录和两个文件。`id` 用下面同一条路径段规则。已存在则 400，不覆盖。
- `GET /api/experts`：返回可勾选领域。`id` 就是目录名，界面也显示目录名，不再另做 title。没有非空 `rules.md` 的子目录不返回。`knowledge_base/index.md` 是库清单，不是一个领域。
- `id` 必须是单一路径段：不允许空串、`/`、`\`、`..` 和控制字符。读文件前把路径解析到 `knowledge_base/<id>/` 之下，越界 400。只写「目录必须存在」挡不住 `../people`。
- 勾选的读写走现有 `PATCH /api/sessions/:id`。现在这个接口**只接受 `title` 并只做改名**。改成 `{ title?: string, experts?: string[] }`，两个都缺则 400；只带 `title` 时行为与现在相同。`experts: []` 表示清空。未知 id、超过 2 个，400。

勾选的界面在前端，名单以这条会话上的 `experts` 为准。只留在前端内存里，刷新或换端之后服务端不知道该带哪一套。

- 切换后立刻保存。保存失败则勾选退回上一次成功的名单，并提示没保存上。
- 发送使用的是这条消息开始装配时已经保存的名单。勾选和发送几乎同时发生时，先等保存完成再发，避免界面已是「理财」、发出去的仍是「情感」。
- 正在生成的那一轮不改。它的系统提示已经装好，取消或改勾从下一条消息起生效。
- 已生成的回复不改写。取消勾选后，旧规则不再注入，但上文仍在。
- 已勾 2 个时再点第三个：界面不让勾，服务端也拒绝。不自动换掉其中一个。要换，先取消再勾。
- 持久化不能只加 `Session.experts`。`createMetadataMessage` 和 `loadSession` 都是白名单，漏一处则勾选写进去、下次读出来就没了。
- 下发给客户端的会话也是白名单。`websocket.ts` 的 `sessionLoaded`、`toSessionMessage`、`protocol.ts` 里的 session 类型都没有多余字段。阶段 2 要三处一起加 `experts`，否则服务端存了、界面上看不到。
- 勾选控件有四个入口，不是一个：桌面聊天、移动端聊天、人物页、心得会话。列表来自接口，不写死「情感 / 理财」。

建完之后的修改走文档浏览器。`knowledge_base` 在文档接口里可写，Agent 不能用 `write` 直接改，只能 `propose_change`。

第一版不做「按问题自动勾选」。勾或不勾由人决定。自动勾选会在用户没打算用这套规矩时把规则塞进去。

## 6. 明确不做

| 项 | 原因 |
|---|---|
| 另建 `experts/` 目录 | 和 `knowledge_base/` 重复，同一篇文章两个家 |
| 把文章全文注入 | 领域一长，固定前缀每轮都变贵；正文用 `read` 已经读得到 |
| 新增文章时自动改 `index.md` | 会冲掉人写的一句话。创建只发生一次 |
| 重复调用创建去覆盖已有 `rules.md` | 人改过的立场不能被模板盖掉 |
| 用 `_index.md` 当目录 | 只有文件名，模型不知道该打开哪篇 |
| 把领域规则写进 `AGENT.md` 或 `instructions.md` | 没勾选的对话也会带上 |
| 向量、自动摘要、按问题自动勾选 | 原文加手写目录已经能指路。检索要加，也是加在「读哪一篇」之后，不替代文件 |
| 一次勾超过 2 个或合计超过 2000 token 仍注入 | 固定前缀膨胀，和上下文预算对着干 |
| 超限时截断规则 | 半段立场比不注入更危险 |
| 把人物原话、心得笔记和领域文章合成一次检索 | 三种资料混在一个排序里会互相污染 |

## 7. 和现有方案的关系

- `plan_distill.md`：蒸馏继续服务笔记和知识库的加速地图，默认仍不注入。领域勾选不读 `distill/`。
- `plan_unified_memory.md`：原文仍是唯一可核对的事实。这一版不建节点、不加向量。
- `context_governance_plan.md`：领域块是新的一格，由人勾选后进入窗口，不进记忆四层的配额。它不参与块与块之间的淘汰，只受自己的 `max` 约束。

## 8. 开工判定

阶段 1 与阶段 2 都已完成并测绿（服务端 `pnpm build` + `pnpm test --run` 595 条，
移动端 `flutter analyze` + `flutter test` 64 条）。上面几节已经按现有代码改过：会话
metadata 白名单、`sessionLoaded` 白名单、`PATCH` 只改标题、预算不按优先级丢块、
整理和对话共用 `chatStream`、`index.md` 写长会连带挤掉规则。

阶段 2 最容易漏的是**下发白名单**：服务端存了但没下发，界面上就是看不到勾选。
现在 `toSessionMessage`、`websocket.ts` 的 `sessionLoaded`、`protocol.ts` 的 session
类型三处都带了 `experts`，并且有测试断言广播里也有。
