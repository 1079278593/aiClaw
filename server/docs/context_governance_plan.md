# 上下文治理：已定规则

> 面向「心得」模块的私人助理。配套机制说明见 `chat_loop_and_context.md`。
> 状态：**已实现**（`memory/inject.ts`、`chat/dialogue-state.ts`、`chat/dialogue-fold.ts`，测试 `memory/quota.test.ts`、`chat/dialogue-state.test.ts`、`chat/person-fold.test.ts`）。判据是会话自己的 `fold: true`：心得那条会话与人物分析会话都走这套，普通聊天不走（见 `plan_people_reply.md` §7 阶段 3）。

## 0. 一次提问里有什么

不按 Working / Episodic / Semantic / Procedural 重做目录。按「怎么进窗口」分。本项目的文件已经是这个方向。

```text
系统提示词
分层记忆（各层自己的上限）
当前有效的对话状态（一份，不含沿革）
尚未收进状态的原文（含最近 2 轮，也含更早但游标还没盖住的轮次）
这一次的新问题
```

| 格子 | 放什么 | 怎么进窗口 | 现有对应 |
|------|--------|------------|----------|
| 常驻小块 | 身份、画像、当前关注、草稿 | 每轮都带，各层有上限 | `AGENT.md`、`user.md`、`focus.md`、`runtime.md` |
| 按问题检索 | 长期事实 | 只带和这句话相关的几条 | `longterm.md` |
| 按需去读 | 心得、知识库、蒸馏摘要 | 不预装，用 `read` / `grep` | `reflections/`、`knowledge_base/`、`distill/` |
| 尚未收进状态的对话 | 游标之后的原文，包含最近 2 轮 | 原文进入窗口 | `session.messages` |
| 已收进状态的对话 | 游标及以前的原文 | 不进入窗口；只注入「当前有效」 | `agents/main/dialogue-state.md` |
| 旧观察 | 以前读过的大段文件 | 游标还没盖住的保持全文；盖住之后再缩短 | 历史里的 `tool` 消息 |

`distill/` 仍只摘要笔记和知识库文件。心得对话的状态不写进 `distill/`。人物模块本次不改。

`runtime.md` 不改名。它最多 2KB、每轮带上，就是一小块常驻草稿。

## 1. 记忆：按层配额

现状（改前）：`INJECT_MAX = 8` 是总条数。`user`、`focus`、`runtime` 先占名额，剩下的才给 `longterm`（`memory/inject.ts`）。

规则：四层不再共用这 8 条。先按该层条数上限选取，再受该层 token 硬顶约束。超出硬顶的条目整条不注入，从该层最旧、未置顶的开始丢，不写成半条，也不占用别的层。`longterm` 在自己的额度里按相关性选取。

单条注入维持现有截断：正文最多 600 字（`formatEntry`），中文估算约 400 token。因此条数上限和 token 硬顶必须同时装得下，不能一边写 4 条、一边只给 400 token。

| 层 | 条数上限 | token 硬顶 | 策略 |
|----|----------|------------|------|
| `user` | 4 | 2000 | 常驻。硬顶内全带 |
| `focus` | 3 | 1500 | 常驻。硬顶内全带 |
| `runtime` | 3 | 1500 | 常驻。硬顶内全带 |
| `longterm` | 5 | 2500 | 按问题打分，只带命中 |

硬顶合计 7500。`MEMORY_TOKEN_MAX` 从 1500 改为 **7500**（已实现，定义在 `memory/types.ts`）。这是上限：短条目只占实际长度。相对模板里的上下文窗口（默认 10 万，现网模板曾到 50 万）仍然是小常驻块。

## 2. 心得对话：窗口里的原文，和删不掉的状态

只处理 `app_state.reflectionsSessionId` 这一条。聊天列表里的其它会话仍走现有的 `compactSession`。不改 `keepRecentRounds` 的全局默认值。

会话 jsonl 在会话还在时保留原文。一轮按用户消息切开，和 `groupByTurn` 一样，助手的 `tool_calls` 与随后的 `tool` 结果跟在同一轮里，不能拆开。

窗口里的历史是：`foldedThrough` 之后的全部原文，再加这一次的新问题。最近 2 轮只是「不许收进状态」的保护区，不是窗口的全部。游标还没盖住的更早轮次继续进入窗口，直到这一批被成功收进状态。收成功之后，这些原文才退出窗口。

### 2.1 游标

`dialogue-state.md` 里按会话 id 记下 `foldedThrough`：已经收进状态的最后一条消息 id。没有这条记录就视为还没收过。

下一条用户消息装配之前，取出「`foldedThrough` 之后、最近 2 轮之前」的消息。这段用 `estimateTokens` 估算超过 **8000** token 才调用模型。8000 只决定要不要调用，不把这段从窗口拿掉。不按窗口的 70%，也不每轮调用。还没成功提交的原文，仍在本次要发送的历史里。

找不到 `foldedThrough` 指向的消息时（会话已被清空），不猜，把这条会话的「当前有效」保留，游标停住，本次不调用收状态模型，并记日志。窗口仍带 jsonl 里现有原文，不把中间轮次拿掉。

模型用现有压缩配置：`config.compaction.provider` 和 `config.compaction.model`。这一批本身超过该模型的上下文时，按更早的轮次切成放得下的几段，按时间从旧到新处理。一段成功就更新「当前有效」和游标，这一段退出本次窗口，再处理下一段。某一段失败就停，已成功的段保留，未成功的原文仍随本次用户消息发送。

### 2.2 当前有效与沿革

模型的输入只有两样：该会话的「当前有效」一块（还没有就是空），加上这一批尚未收过的原文。不读沿革，也不读游标以前的 jsonl。

输出仍是固定角色，没有的写「无」，不规定字数：

- 原样保留：硬性约束、数值、名称、用户原话要求。这一批没有明确推翻的，必须逐字抄进新的一块
- 收成结论：已做决定及理由、未决问题和阻塞、偏好与禁忌；被否决的方案只留方案和原因；讨论只留结论
- 丢掉：寒暄、确认性回复、已被推翻的中间结论、和后文无关的枝节

成功则：原来的「当前有效」整块挪到「沿革」，标上时间，正文不再改；新的一块成为「当前有效」；`foldedThrough` 挪到这一批的最后一条消息。失败则游标不动，旧的「当前有效」不动，本轮仍把未处理的原文发给模型，只记日志。

窗口只注入**当前这条心得会话**的「当前有效」。沿革不注入。其它会话 id 的块不注入。因此删掉心得会话再新建一条时，旧状态还在文件里，新会话不会带上它。

「当前有效」超过 **2000** token 视为失败，不更新、不挪游标。这样注入体积是一块，不是按批数增长。

文件是 `agents/main/dialogue-state.md`。每个会话 id 一块，形状固定为 `foldedThrough`、`当前有效`、`沿革`。不进 `distill/`。删除会话不删这个文件。注入时放在系统块里，单独占用最多 2000 token，超限整块不注入并记日志，不截成半块。

不要调用 `compactSession` 来做这件事。它会把最近 2 轮以外的历史整段再摘要，旧状态会被重写。

手动压缩这条心得会话时不看 8000 token，有待处理原文就走同一条路径。聊天列表里的手动压缩仍是 `compactSession`，不受影响。

只在两次用户消息之间做，不在同一次提问的工具循环里做。

## 3. 大工具结果：当轮全文，历史按字节缩短

`read` 单次最多 50KB。这段原文在同一次提问的循环里必须保留。不要在 Phase 5 里截断，下一轮模型还要用。

心得会话里，消息 id 还在 `foldedThrough` 之后的工具结果保持全文，包括已经不在最近 2 轮、但还没被收进状态的那些。等这一轮已经被游标盖住之后，才把其中超过 **4KB** 的 `tool` 改成机械记录：工具名、路径或查询、原字节数、以及工具自己带的截断说明。不为此再调一次模型。收状态看的是用户和助手正文加上当时还未缩短的工具结果。先缩短再收状态，这一批的工具正文就没了。

聊天列表里的会话本次不缩短。

不按工具名豁免。`grep` 最多 200 条，行很长时仍可能超过 4KB，一样缩短。4KB 以内的结果保持原文。

## 4. 明确不做

| 项 | 原因 |
|----|------|
| 按四个学术层重命名文件 | 不改变进窗口的方式 |
| `runtime` → `scratch` 及迁移 | 要动现有数据；2KB 常驻草稿已经够用 |
| Phase 5 内截断工具结果 | 当轮后续推理看不到刚读到的内容 |
| 用模型为每条工具结果写一句摘要 | 多一次调用；助手回复里已经有结论 |
| 把旧对话换成路径说明 | 对话没有另一份原文可再读 |
| 占窗口 70% 才压缩，或每轮全量重总结 | 触发要么太晚，要么把已有状态反复改写 |
| 把心得对话写进 `distill/` | 笔记蒸馏可以丢掉重建；对话状态不行 |
| 这次改人物的原文、简报或档案 | 人物已有自己的整理；本次只定心得会话 |
| 只在会话第一轮注入 `runtime` | 前后轮系统块不同，前缀缓存失效 |
| 压缩失败时丢弃旧对话 | 失败应保持原历史，不能静默丢 turn |

## 5. 写代码时动这三处

1. `memory/inject.ts`：按 §1 分层配额。`MEMORY_TOKEN_MAX` 改为 7500。上下文来源页显示各层实际注入条数。
2. 两次用户消息之间：按 §2 处理心得会话。只把游标之后、最近 2 轮之前、且超过 8000 token 的原文收进「当前有效」；未到 8000 的仍进入窗口。旧块进入沿革并且不注入。手动压缩不看 8000，有待处理原文就收。
3. 心得会话里，某一轮已经出现在 `foldedThrough` 覆盖范围内之后：按 §3 缩短超过 4KB 的 `tool`。游标还没盖住的不缩短，包括最近 2 轮以外、尚未收进状态的。当轮 `extraMessages` 仍用全文。

## 6. 和循环文档的关系

同一次提问里，阶段 A 装好的头部在循环中不改，工具结果只追加。这是前缀缓存能命中的范围。

下一次心得提问会重新检索记忆，并带上：记忆配额内的条目、该会话的「当前有效」一块、游标之后的全部原文（含尚未缩短的工具结果）。游标以前的原文不带，沿革和其它会话的状态不带。厂商 KV cache 只省钱，不代替这些裁剪。
