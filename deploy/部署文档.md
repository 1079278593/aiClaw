# aiClaw 发布到 NAS（绿联）

Mac 负责改代码和构建镜像。NAS 只跑这一个容器。手机端、测试、Mac 的 `.env` 和 `start.command` 不进镜像。

用户数据也不进镜像。会话、`auth/users.json`、每个账号的 `config.json`（含模型密钥和 Trilium）都在数据目录里，用卷挂进去。

| 位置 | 里面有什么 |
|------|------------|
| 镜像 `aiclaw:local` | 编译后的服务端、网页静态文件、初始化模板 |
| NAS `/volume1/docker/aiclaw/data` | `auth/`、`tenants/`、`logs/` |
| NAS 项目目录里的 `aiclaw.env` | 只有 `AICLAW_DATA_DIR=/data`，没有密钥 |
| 源码仓库 | 全部。`deploy/*.tar` 不提交 |

Mac 上的 `server/.env` 继续指向这台电脑的数据目录。发版不要改它。

---

## 首次

### 1. NAS 上准备目录

在绿联上建好 `/volume1/docker/aiclaw/`，里面放：

- `aiclaw.env`：从 `deploy/aiclaw.env.example` 复制，内容保持 `AICLAW_DATA_DIR=/data`
- `docker-compose-aiclaw.yml`：用仓库里的 `deploy/docker-compose-aiclaw.yml`
- `data/`：空目录，或从 Mac 拷来的现有数据

沿用这台 Mac 的账号和会话时，把 `/Users/ming/aiclaw-data` 拷进 `data/`。里面应有 `auth/users.json` 和 `tenants/`。不要把 Mac 的 `server/.env` 拷过去。

`tenants/default/config.json` 里的 `server.host` 要是 `0.0.0.0`。容器里如果写成 `127.0.0.1`，端口映射进不去。

### 2. Mac 构建，得到 tar

打开 Docker Desktop。双击 `deploy/发布.command`，选 2，再选完整选项，导出位置选 NAS 目录。得到的文件是 `aiclaw-local.tar`。

这个文件名只是包。包里面的镜像名是 `aiclaw:local`。把 tar 放进项目目录，不会变成 Docker 镜像。

### 3. 在绿联里导入镜像

**Docker → 镜像 → 导入**，选中 `aiclaw-local.tar`。

导入完成后，镜像列表里必须出现 `aiclaw:local`。没有这一行，项目会报 `No such image: aiclaw:local`。Compose 不会自己读取旁边的 tar，也不会去 Docker Hub 下载（`pull_policy: never`）。

列表里的名字如果不是 `aiclaw:local`，把 compose 的 `image:` 改成列表里的名称和标签。

### 4. 创建项目

镜像列表里已经有 `aiclaw:local` 之后：**Docker → 项目 → 创建**（不要用「容器 → 创建」）。目录选 `/volume1/docker/aiclaw`，Compose 选 `docker-compose-aiclaw.yml`。

快速发版（脚本选项 1）会用 SSH 执行 `docker load`，等于代替这一步的手动导入。第一次如果还没有在界面里建过项目，仍要做上面的「项目 → 创建」。以后改代码只重复快速发版，不必再导入。

> **SSH 免密的前提**：快速发版靠密钥登录（脚本用 `BatchMode=yes`，不接受密码）。
> 密钥要一次性配好，配置与故障排查见 [SSH免密排查.md](SSH免密排查.md)。
> 若报 `Permission denied (publickey,password)`，**镜像和 tar 已经构建成功，不必重建**，
> 修好 SSH 后直接重跑部署脚本即可。

### 5. 验收

在 NAS 上：

```bash
curl -s http://127.0.0.1:3010/health
```

应返回 `authRequired: true`。同一局域网的浏览器打开 `http://guobao.local:3010`。端口是 `3010:3000`：NAS 上用 3010，容器内仍是 3000。

容器里管理账号：

```bash
docker exec -it <容器名> node dist/cli/index.js user list
```

## 以后改代码

双击 `deploy/发布.command`，或：

```bash
./deploy/script/release.sh
```

直接回车是全部：先提交已有改动，再发 NAS 和 fir（只发 iOS），最后把发版号提交并推到 GitHub。第 2 项进入原来的 NAS 导出菜单：快速发版，或只导出 tar（可选架构和保存位置，不自动重启）。也可以只选 fir，或只提交并推送。推 GitHub 时使用系统代理，并用已登录的 `gh` 认证。

只换 NAS 镜像时仍可：

```bash
./deploy/script/docker-export-for-nas.sh --quick
```

脚本会把仓库里的 `deploy/docker-compose-aiclaw.yml` 覆盖到 NAS 项目目录，再重建容器。端口保持 `"3010:3000"`。不要在 NAS 上改成 `127.0.0.1:3010:3000`，否则只有 NAS 本机能连。若重建后容器仍只绑在 `127.0.0.1`，脚本会失败退出。`data/` 不动，账号和密钥还在。

发版脚本卡在 SSH 报 `Permission denied (publickey,password)` 时，见 [SSH免密排查.md](SSH免密排查.md)。

## App 内「检查更新」

手机端「更多 → 检查更新」由**服务端代理**去问 fir，App 里没有 fir 的 token。

为什么不把 token 打进 App：`FIR_API_TOKEN` 是**账号级**凭证，用它不只能查版本，还能列出账号下所有应用；而 IPA/APK 都能被解包，token 相当于对每个拿到安装包的人公开。所以 token 只待在 NAS 上。

启用步骤：

1. 在 fir.im 账号设置里生成 API Token。
2. **用脚本一次改好所有租户**（推荐）：

   ```bash
   # 在 NAS 上，或从 Mac 通过 SSH 执行
   FIR_API_TOKEN=你的token ./deploy/script/add-app-update-field.sh           # 先预览
   FIR_API_TOKEN=你的token ./deploy/script/add-app-update-field.sh --apply --enable
   ```

   脚本会遍历 `data/tenants/*/config.json`，**只补缺失的 `appUpdate`**，
   已有的原样跳过（幂等）；改前自动备份 `config.json.bak-<时间戳>`；
   写完立刻复核 JSON，最后重启 `aiclaw-aiclaw-1`。

   手动改也行，路径是 `data/tenants/<用户名>/config.json`。
   **没有 `data/config.json` 这个文件**——配置是按租户分开存的，先看有哪些：

   ```bash
   ls data/tenants/
   ```

   （只有在没有 `tenants/` 的老安装上，配置才会落在 `data/config.json`。）

   要加的段（和 `providers`、`server` 同级）：

```json
"appUpdate": {
  "enabled": true,
  "apiToken": "你的 fir API Token",
  "apiBase": "https://api.bq04.com",
  "iosBundleId": "com.aiclaw.aiclawMobile",
  "androidBundleId": "com.aiclaw.aiclaw_mobile",
  "timeoutMs": 15000
}
```

   改错租户目录的表现是「更多」页没有「检查更新」——读到的 `enabled` 还是 false。

3. 重启容器让配置生效（配置只在启动时读入）。接口验证：

```bash
curl -H "Authorization: Bearer <你的 accessToken>" \
  "http://<NAS>:3010/api/app/update?platform=ios"
```

返回里 `configured:true` 且 `available:true` 即为正常，`installUrl` 就是 App 里点「立即安装」跳的地址。

行为约定：

- **不自动弹窗**。只在「更多」页点「检查更新」时才查，避免每次启动都打扰。
- 判断有无新版以 **build（构建号）** 为准，相同再比版本名；两个都读不到时不提示（宁可漏提示，不误报）。
- 服务端没配 `appUpdate` 时接口返回 `configured:false`，App **隐藏**该入口，而不是显示一个点了就报错的按钮。
- Android 尚未上传过包时 fir 返回 `app is not found`，接口按正常空结果处理（`available:false`），不算故障。
- 安装走 `itms-services`，由 iOS 系统安装器接管：直接覆盖当前版本，不在「文件」里留下 ipa。`Info.plist` 已声明该 scheme。

  这里有个容易踩的坑：fir 的 `installUrl` 返回的是 **manifest plist**
  （`Content-Type: application/x-plist`），不是网页。直接打开它，Safari
  只会把 XML 显示出来或当成文件下载——表现就是「能下载，但装不上」，
  而且会在「文件」里留一份管不到的 ipa。必须先包一层：

  ```
  itms-services://?action=download-manifest&url=<URL 编码后的 installUrl>
  ```

  App 已经这么处理了（`mobile/lib/src/app_update.dart` 的 `installTarget`）。
  `update_url` 是 HTML 下载页，客户端**不拿它兜底**，否则又回到下载的老路。

排查「更多」页看不到「检查更新」：

1. 先确认改的是**你登录账号**的 `data/tenants/<用户名>/config.json`，不是别的租户目录。
2. 用 curl 验证接口。返回 `configured:false` 说明服务端没读到 `apiToken`（多半是 `enabled` 还是 false，或改错了文件）。
3. 返回 `configured:true` 但 `available:false` 且 reason 提到「没有安装包」，说明 token 没问题，是 fir 上还没这个 bundle 的包。
4. `reason` 里出现「fir 拒绝了请求」，通常是 token 填错，或模板里的占位文字没替换。

## 不发布的东西

| 不进 NAS 镜像 | 原因 |
|---------------|------|
| `mobile/` | 手机端单独编译安装 |
| `server/.env` | 只属于这台 Mac |
| `tenants/`、`auth/` | 运行数据，走卷 |
| 测试、`node_modules` 源码树 | 镜像里只留生产依赖和 `dist` |
| `start.command` | Mac 双击启动，NAS 用 Compose |

## frp

继续用 NAS 上现有的 frp。内网目标可以是 `127.0.0.1:3010` 或 `guobao.local:3010`。阿里云那边用 HTTPS 转到 frp，不要把 3010 直接暴露成公网 HTTP。frp 的令牌留在 NAS 的 frp 配置里，不写进这个仓库。

备份时快照整个 `data/`，至少包括 `auth/` 和 `tenants/`。
