# 聊天记录与人物档案

本文说明怎样按 id 建立一个人，把和这个人有关的话收进原文，以及怎样把这些话写成历史简报。手机、iPad 和桌面网页共用这里的行为。界面怎么摆见 [client_surfaces.md](client_surfaces.md) 第 4 节。字段见 [api_shapes.md](api_shapes.md) 第 7 节。咨询仍走 [session_runtime.md](session_runtime.md) 里的助手会话，人不持有会话。

当前代码还没有这条路径。`inbox/` 只保留一个本质：内容落在数据目录里，图片是文件，语音最后只剩文字。独立进程、单独 token、群聊、每条必填说话人，不在本文里。

## 1. 人是主线

一个人只有一个 `id`。称呼、昵称、简称都是这个 id 上的叫法，用来显示和判重，不用来做目录，也不写进原文的说话人字段。

进入一个人之后有三块：原文、历史简报、咨询。档案是旁边的分栏资料，不是这三块之一。

原文是对话本身，按录入顺序增长。历史简报按录入时间写成阶段性摘要，不是第二份对话。档案是这个人的分栏资料。

| 东西 | 作用 | 谁可以改 |
|---|---|---|
| 原文 `entries.jsonl` | 一句一句的原话、自述、以及识别成功后的句子 | 录入、改字、改说话人、删除 |
| 历史简报 `digest.md` | 按月份和事情概括原文。不逐句抄，不分左右 | 只有历史简报成功时由服务端改 |
| 档案 `profile.md` | 称呼、昵称、简称和其它事实。不放对话 | 历史简报运行，或在档案页手改 |

聊天列表的主体是「我」。咨询不按人各建一条。选中一个人之后，发出去的消息带上档案全文，并带上历史简报和原文的路径。了解经过先读历史简报。只有用户明确要看原文或原话时才读原文。

## 2. 材料怎么进来

微信一类的记录导不出来，所以原文里会有三种内容：

- 一句一句抄。开关打开时是右侧的自己，关闭时是左侧的这个人。
- 自述。一段话里可以同时有情景、记得的对话和自己的想法，先按原样留下。
- 截图。选中后立刻识别。成功则写成原文里的句子，图片不保存。失败则提示，不产生条目，也不留文件。

语音用系统自带的识别，不接按量计费的云识别。iOS 用系统 Speech，Android 用系统 SpeechRecognizer，Flutter 侧用 `speech_to_text` 调用这两套。不向本服务上传音频。安静环境下、一句一句说中文，够用；名字、很长的自述和吵闹环境会飘，识别结果先留在输入框里，用户改完再发送。输入框里原来的字保留，新识别接在末尾，字变多后输入框滚到最新一行。正在听时麦克风有持续的反馈，系统识别停下后反馈一起停。桌面网页没有这套系统识别时，不另接一家云服务，输入框仍可打字。

## 3. 版面

大屏幕左、中、右同时在：

| 栏 | 内容 |
|---|---|
| 左 | 全部的人。可在「最近」和「按名」之间换。按名就是档案库 |
| 中 | 默认是原文。可换成历史简报或档案 |
| 右 | 咨询。上方标明这条消息会带上谁的档案 |

中栏分段只切换中栏：原文、历史简报、档案。历史简报页只阅读已保存的摘要，没有输入框，也不能改字。原文页才有录入框。咨询输入框上有「整理」按钮。历史简报是版面，整理是这个按钮。

手机底部是聊天、人物、文档、更多。聊天仍是原来的会话首页。点进一个人默认是原文。导航栏有「历史简报」「档案」「咨询」。

iPad 竖屏左栏是名单，右栏默认原文，可换成历史简报、档案或咨询。

文档工作区和人物工作区来回切换时，不取消正在生成的运行。换人也不取消，只改变下一句要带的档案。

## 4. 对象

```text
inputs/people/<id>/
  meta.json
  entries.jsonl
  profile.md
  digest.md
```

`<id>` 用 UTC 时间 `YYYYMMDDTHHMMSSZ` 加 4 位随机字符。目录名不用称呼。建立时写下第 7 节的空档案，以及只有版本头的 `digest.md`。没有图片目录。

`meta.json`：

| 字段 | 用途 |
|---|---|
| `id` | 身份。改称呼、昵称、简称都不改变它 |
| `name` | 称呼，和档案「基本信息」里的称呼保持同一句 |
| `nicknames` | 昵称。没有则为空数组 |
| `shortNames` | 简称。没有则为空数组 |
| `createdAt` `updatedAt` | 建立时间，以及最近一次原文变动的时间 |
| `organizedAt` | 最近一次整理成功时，交进去的最后一条原文的 `at`。没有成功过则省略。这是末尾，不是当时的时钟 |

原文一行一条。界面从上到下显示，新的在最下面。往上翻一次取 50 条。每一条：

| 字段 | 用途 |
|---|---|
| `id` | 条目 id，只用于修改、删除和写历史简报时对准。不拿来显示 |
| `at` | 录入时间。写入后不再修改 |
| `kind` | `line` 或 `note` |
| `speaker` | 只有 `line` 有。`me` 或 `them` |
| `text` | 文字。可以含换行 |

`me` 画在右侧，标「自己」。`them` 画在左侧，标当前称呼，也就是这个聊天对象。说话人字段只存 `me` 或 `them`，不写称呼。顶部导航栏显示称呼。称呼可以改，`id` 不变。

每个人在内存里有一份未发送草稿。切到别人再回来，草稿还在。退出登录或 `4401` 时丢掉全部草稿。

## 5. 建立这个人

新建时填一个称呼。空白不能建立。

```text
称呼、昵称或简称与已有的人相同
  -> 不新建
  -> 打开那个人的原文

还没有
  -> 新建 id
  -> name 和档案里的称呼都写成这个字符串
  -> nicknames、shortNames 为空
  -> 进入原文页
```

之后改称呼，改的是这一个 id。已有原文的 `speaker` 不动。历史简报不因为改称呼而重写。档案里的称呼若仍等于旧称呼，一起改成新的；用户已经改过的称呼不动。昵称、简称可以有多项，在档案里用顿号分隔。手改档案并保存时，把这三项写回 `meta.json`。

## 6. 原文

时间轴只用录入顺序和录入时间。不提供发生时间，也不提供修改 `at`。补记是滞后的，发生在哪一天写在文字里。界面按录入日期分组，标题写「录入」。

一句原话立刻成为一条 `line`。自述成为一条 `note`，不拆开。

点一条可以改文字；`line` 还可以改 `speaker`。位置和 `at` 不变。删除前确认「删除这条」。

`at` 不晚于 `organizedAt` 的原文，是已经整理过的。之后再改字、再删，历史简报不动，下次整理也不读它们。`at` 更晚的原文还没整理。这些改字、删除只改原文本身；下次整理读的是当时还在的全文。历史简报页在末尾之后还有原文时显示「还有原文没写入历史简报」。

### 6.1 输入

输入只在原文页。开关文案是「自己」。打开为 `me`，气泡在右；关闭为 `them`，气泡在左，默认关闭。这个人的原文页还开着时记住上次的开关。换成「自述」时藏起开关，保存为 `note`。

```text
line 且文字为空 -> 不能发送
note 且文字为空 -> 不能发送
listening -> 先停止识别并提交最后一句
saving -> 再次点发送，直接忽略
```

语音的临时结果不进草稿。拒绝权限时提示「需要语音识别权限」。识别失败只丢掉临时结果。正在听的反馈跟着系统识别状态。

发送成功则追加到 `entries.jsonl` 末尾并清空草稿。失败则草稿保留。

### 6.2 截图

选图或在桌面粘贴图片后立刻识别，不先存文件。使用当前选中的模型。一次最多 20 张，单张不超过 5 MiB，只接受 PNG、JPEG、GIF、WebP。

```text
当前模型 modal 不是 vl
  -> 不上传
  -> 提示「请切换到视觉模型后再识别」

某一张识别失败，或结果里没有句子
  -> 这一张不产生条目，不留文件
  -> 提示「识别失败」
  -> 同一批里已经识别成功的其它张照常写入

识别成功
  -> 按画面从上到下，只把双方说过的话写成 line
  -> 靠右 speaker=me，靠左 speaker=them
  -> 时间、系统灰字、「撤回了一条消息」丢弃，不写成条目
  -> 丢弃图片字节

左侧出现两个及以上不同的人，或画面是群聊
  -> 这一张不产生条目，不留文件
  -> 提示「这是群聊，不能放进个人对话」
```

同一轮里若还有文字，先写文字条目，再写识别出的句子。识别不进入咨询，也不改历史简报和档案。

## 7. 档案格式

`schemaVersion` 为 1。栏目固定。对话不进档案。没有字数上限。同一件事改原来的一行。

```markdown
---
schemaVersion: 1
---

## 基本信息
- 称呼：
- 昵称：
- 简称：
- 关系：
- 如何认识：
- 身份或工作：
- 所在：

## 个人资料

无

## 近况

无

## 和我之间

无

## 我的判断

无

## 待核

无
```

| 栏目 | 放什么 | 怎么变长 |
|---|---|---|
| 基本信息 | 上面七项。昵称、简称可以多项 | 称呼只留当前值。昵称、简称合并重复项 |
| 个人资料 | 相对稳定的个人情况 | 新事实加一行，重复的合并 |
| 近况 | 现在正在发生的事 | 过时的删掉，这里不是日志 |
| 和我之间 | 约定、未了结、和我有关的反复事项 | 办完或作废的移走 |
| 我的判断 | 只有我表达过的判断 | 改口就替换 |
| 待核 | 还不能当成事实的 | 核实后移走 |

手改时七项标题和后面五个栏目标题都要在。缺标题则不保存。

## 8. 历史简报

整理由咨询输入框上的「整理」按钮发起，结果写进历史简报这个版面。没有选中的人，或没有 `at` 晚于 `organizedAt` 的原文时，按钮不可用。点下去就是这一条咨询里的一轮对话：用户侧显示「整理目前新增的内容。」回复按平常的方式流式出现在咨询里。不改写这段回复的措辞。

服务端只附上现有历史简报、现有档案，以及 `at` 晚于 `organizedAt` 的原文。还没有 `organizedAt` 时，附上全部原文。末尾及更早的原文不读、不附。

说明原文：

```text
已有历史简报在下面。这次只附上次整理末尾之后的原文。每条带 speaker 或 kind：speaker=me 是用户自己，speaker=them 是对方，kind=note 是用户写下的自述。

根据下面这次的原文，写历史简报。
保留重要信息，表达中心意思。废话和没有实质内容的不收录。改变了经过的短句要留下。
只写原文里有的，不补充原文没有的内容。人名和数字用原文里的词。
标明属于自己或对方的，仍属于这一方。自述不要写成某一方说的话。
已有历史简报不要重写。这次只写新增的一段，接在后面。

若档案需要按这次原文修改，在简报正文之后以 <<<档案>>> 开头，给出完整档案。不需要改就不要写档案。
不要修改 entries.jsonl。
```

右侧气泡和会话记录里只保留 `<<<档案>>>` 之前的正文。这段正文追加进 `digest.md`。`<<<档案>>>` 之后的栏目齐全时，写成 `profile.md`，并同步称呼、昵称、简称。栏目不齐或没有这一段，档案保持原样。调用失败或正文为空时，历史简报和档案都不改，咨询里显示这次的错误，与其它对话失败相同。成功后把 `organizedAt` 写成这次交进去的最后一条原文的 `at`。

普通咨询不写这两个文件。

正在看的原文或历史简报，和打开一篇 `inputs` 文章一样。桌面用鼠标选中文字，手机长按选中。下一条 `chatMessage` 在开关打开时带 `previewPath`：看历史简报时是 `digest.md`，看原文时是 `entries.jsonl`。有选区再带 `selectedPreviewText`，内容只是选中的文字。

用户在咨询里要求修改时，走现有的写文件和写权限。历史简报改的是 `digest.md`。原文改的是选中文字所在的那一条，只改文字，位置和录入时间不变。发送成功后清除选区。

## 9. 档案库

和聊天列表是同一批 id。聊天按 `updatedAt`。档案库按称呼排序。从档案库点进去先看档案，可以再打开原文或历史简报。

删除一个人只删除这个目录。咨询用的会话不删。

## 10. 咨询时带什么

选中一个人时，下一句带 `threadPath`。正在看原文或历史简报时，再按上面的规则带 `previewPath` 和选区。关掉咨询栏上的称呼后，下一句不再带 `threadPath`。

| 材料 | 每条消息里放什么 |
|---|---|
| 档案 | 全文。放不下时只留路径，不截断半个栏目 |
| 历史简报 | 只留 `digest.md` 的路径 |
| 原文 | 只留 `entries.jsonl` 的路径 |

```text
<系统提示>
使用者是「我」。右侧「自己」是我，左侧是 id 为 {id} 的人。称呼、昵称、简称见档案，身份以 id 为准。
档案正文：
{profile.md 全文，或放不下时的路径}
历史简报路径：inputs/people/<id>/digest.md
原文路径：inputs/people/<id>/entries.jsonl
了解这个人先用档案。了解一段对话经过什么，先分段读历史简报。历史简报是摘要，不是原话。
只有用户明确要看原文或原话时，才分段读原文。
</系统提示>
```

不自动发送。写进知识库只在用户于咨询里明确提出之后发生。

## 11. 回归场景

1. 用已有称呼、昵称或简称建立：打开原来的 id，不新建目录。
2. 改称呼：顶部导航栏变成新称呼，`id` 不变，已有 `speaker` 不变。右侧仍标「自己」，左侧改显示新称呼。
3. 开关关闭时发送：`speaker` 为 `them`，气泡在左。历史简报不变，并显示还有原文没写入历史简报。
4. 截图识别成功：原文多出双方说过的句子，没有时间、灰字和撤回。磁盘上没有这张图。
5. 截图是群聊，或左侧有两个及以上的人：整张不产生条目，提示「这是群聊，不能放进个人对话」。
6. 当前模型不能看图时选图：不产生条目，提示切换视觉模型。
7. 修改或删除已经整理过的原文：历史简报正文保持原样，`organizedAt` 不变。
8. 点「整理」：咨询里出现用户句「整理目前新增的内容。」和回复正文。回复不因缺少固定四行而失败。历史简报版面在成功后多出这次正文。
9. 再次整理时，送入的原文只有 `at` 晚于 `organizedAt` 的。`digest.md` 在末尾追加这次正文，已有段落不变。末尾之前的原文不发送。
10. 正在看历史简报并选中一段时，下一条带 `previewPath` 为 `digest.md`，并带 `selectedPreviewText`。用户要求改这段时，改的是 `digest.md`。选中原文的一句并要求修改时，只改那一条的文字。
11. 关掉称呼后发出的消息没有 `threadPath`。
